# CLAUDE.md

Guidance for AI agents working in this repo. Keep this file current when the
architecture or its invariants change.

## What this is

A static web app that finds every block of a given type in a Minecraft save and
plots the coordinates on a map. **The scan runs entirely in the browser** — the
save is never uploaded and there is no server in the scan path. An optional
accounts API handles Google sign-in and scans the user chooses to save. Single-user personal tool. See
`README.md` for the product overview.

- `scanner/` — Rust crate compiled to WebAssembly. The actual scanner.
- `frontend/` — React 19 + TypeScript + Vite (Node 20+). Ships to GitHub Pages.
- `backend/` — the optional accounts API: FastAPI + SQLAlchemy + Alembic on
  Neon Postgres, deployed to Google Cloud Run from its `Dockerfile`
  (`backend/deploy.sh`). Google sign-in,
  sessions, saved scans, account deletion. See `backend/README.md`. (Not the old Python
  scanner — that oracle was removed in `25a0c22`; recover it from git history.)
- `infra/` — Google Cloud cost guards for the API: the billing kill switch
  (`billing-killswitch/`, a Cloud Function that unlinks billing at $1) and the
  image cleanup policy. See "Cost guards" in `backend/README.md`.
- `testing/` — sample save zips for manual checks (`test1.zip` ~1.4 MB,
  `test2.zip` ~1.18 GB).

The root `justfile` is a thin task runner over the commands below (`just` lists
them; `just frontend`, `just backend`, `just dev` for both). It wraps, never
replaces, the per-package scripts. The frontend build drives the scanner build.

## Running & checks

| | Command |
|---|---|
| Frontend dev | `cd frontend && npm run dev` (needs `npm run build:wasm` once first) |
| Frontend deps | `cd frontend && npm ci` |
| Build wasm | `cd frontend && npm run build:wasm` |
| Full build | `cd frontend && npm run build` (wasm → `tsc -b` → `vite build`) |
| Frontend typecheck | `cd frontend && npm run typecheck` (`tsc -b`: app, config and tests) |
| Frontend lint | `cd frontend && npm run lint` |
| Refresh block list | `cd frontend && npm run update:blocks [-- <version>]` |
| Frontend unit tests | `cd frontend && npm test` (Vitest; `npm run test:watch`) |
| Frontend e2e | `cd frontend && npm run build && npm run test:e2e` (Playwright; `npx playwright install chromium` once) |
| Scanner tests | `cd scanner && cargo test` (CI also runs `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`) |
| Backend tests | `cd backend && uv run pytest` (set `TEST_DATABASE_URL` to also check migrations on Postgres) |
| Backend dev server | `cd backend && uv run uvicorn app.main:app --reload` (needs `.env`, see `.env.example`) |

`frontend/src/wasm/` is generated by `wasm-pack` and is **not committed** —
a fresh clone must build the crate before `tsc` will pass, because the
TypeScript build reads the generated `.d.ts`.

Always run `tsc`/`lint` after touching frontend code — the lint config is strict
(see "React Compiler" below).

### Tests and CI

`.github/workflows/ci.yml` runs every layer on each push to `master` and on
PRs into it: scanner (fmt, clippy, `cargo test`), frontend (wasm build, lint,
typecheck, Vitest, production build), e2e (Playwright on the built `dist/`),
and backend (pytest, with migrations also applied to a Postgres service).

- **Synthetic saves, not checked-in fixtures.** `scanner/tests/common/` and
  `frontend/src/test/world.ts` build NBT, region files and whole worlds byte by
  byte, so every test states the exact blocks it plants and the exact count it
  expects. `frontend/src/test/zipWriter.ts` writes zips in the awkward shapes
  real zippers produce (streamed sizes, Zip64, prepended stub, EOCD signature
  in the comment).
- **Unit tests** are `*.test.ts` beside the code, run in Node. They are
  excluded from `tsconfig.app.json` and type-checked by `tsconfig.test.json`
  (which allows Node types); helpers under `src/test/` are never bundled.
- **`pool.test.ts` guards invariant 1** with fake workers that count live
  region buffers. Change the scheduler and that test is what tells you whether
  the bound still holds.
- **e2e** (`frontend/e2e/`) scans the synthetic world as a zip *and* a folder
  in every dimension and asserts identical, exact counts — the automated form
  of the zip/folder check below — plus every static page and the 404.
- **`scanner/tests/robustness.rs`** is the "nothing may panic" check:
  truncations, seeded byte corruption and hostile length fields. Seeded and
  deterministic; raise `ROUNDS` locally for a longer soak.

The `testing/` zips are still the check on real data: run the app against
them — and, for the folder path, against one extracted to a directory. The two
must report identical counts for the same block and dimension.

## Architecture map

Pick a save — a zip, or the world folder itself → a worker opens it and pulls
out one dimension's region files → a pool of wasm workers scans them →
coordinates go on a canvas. No network.

### Scanner (`scanner/`)
Port of the old Python scanner (removed in `25a0c22`), compiled to `wasm32-unknown-unknown` via `wasm-pack`.
`src/nbt.rs` ← `fastnbt.py`, `src/region.rs` ← `parser.py`, `src/lib.rs` is the
`wasm_bindgen` surface (`scanRegion`, `ExternalChunks`, `ScanResult`), and
`src/bin/oracle.rs` is the native CLI used to diff against Python. Full detail,
including why nothing in it may panic, is in `scanner/README.md`.

### Frontend (`frontend/src/`)
Six static entry points (`main.tsx`, `pages/docs/docs-main.tsx`,
`pages/scans/scans-main.tsx`, `pages/legal/privacy-main.tsx`,
`pages/legal/terms-main.tsx`, `pages/notfound/not-found-main.tsx`) mount one
page each from `pages/`. A page
composes components from `components/` and calls into `lib/` for anything that
isn't markup; nothing under `components/` reaches back up into a page.

- `pages/index/Index.tsx` — the app. Owns the three-phase state machine
  (`idle → opening → scanning`), driven from `handleSubmit`, plus the scan's
  inputs and its result. Everything it draws is a component; keep it that way,
  because this file is the only place the whole flow is legible at once.
- `lib/scanOptions.ts` — the vocabulary shared by the page and the form:
  `DIMENSIONS`, `SOURCES`, `MAX_MATCHES`, `Phase`, `ScanResult`.
- `lib/blockTypes.ts` — `BLOCK_TYPES`, the block-type autocomplete, read from
  `content/blocks.json`. That file is generated by `scripts/update-blocks.mjs`
  from Mojang's registry and lang files (via `misode/mcmeta`) and **committed**:
  nothing is fetched at build time or at runtime, so a failed refresh just
  leaves the last snapshot in place. `ScanForm` offers it as a `<datalist>`
  on a free-text input, so modded or newer blocks still scan.
- `lib/sampleWorld.ts` — the sample world, which stands in whenever no save is
  picked (`selectedSave === null` in `Index.tsx`), so a visitor without a world
  can still press Scan; the button reads "Scan the sample world" and a line under
  the picker says it's selected. `assets/sample-world.zip` (~1.2 MB, imported
  `?url`, so it's hashed into `dist/assets/`) holds only
  `sample-world/region/*.mca` from a superflat test save: two nether portals,
  overworld only. Fetched on the first sample scan, inside the `opening` phase,
  then cached; from there it's an ordinary zip `SaveInput`. Unlike the test
  saves it is a real, committed file, because it's a product asset and not a
  fixture. Never add level.dat or playerdata to it (they carry player UUIDs).
- `lib/scanWorld.ts` — spawns the coordinator worker, reports `opened`/
  `progress` back through callbacks, and resolves with the result. Converts the
  flat `Int32Array` of coordinates into `[{x,y,z}]` at the worker boundary, so
  nothing downstream knows about the packed form.
- `components/scan/SavePicker.tsx` — the zip/folder toggle and the file input.
  The input is remounted per mode (`key`) because `webkitdirectory` does not
  toggle reliably on a live input; `readSelection()` here is also where a
  folder's paths are captured (invariant 7).
- `components/scan/` — `ScanForm.tsx` (save, block type, dimension, submit),
  `DimensionToggle.tsx` (the three-stop dimension slider: native radios under a
  draggable thumb, icons from `assets/blocks/*.svg`, which are full-colour pixel
  art rather than `currentColor` icons),
  `ScanProgress.tsx` (both bars), `ScanSummary.tsx` (the result line and bulk
  copy), `MapPanel.tsx` (the square frame the map and its loader live in). All
  controlled by the page; the only state any of them keeps is `ScanSummary`'s
  transient "Copied".
- `components/layout/` — `AmbientBackground` (the `bg-blobs` markup, shared by
  all three pages), `Divider`, `SiteFooter`.
- `workers/source.ts` — where a save's bytes come from, and the only place the
  two input forms differ. Flattens both to `SaveEntry[]` (`name` + `readRaw()`),
  so nothing downstream knows which it got. A loose `.mca` is modelled as a
  *stored* member (`method: 0`), which `decompress()` already passes through
  untouched — that is why the pool needs no special case for folders.
- `workers/zip.ts` — the zip reader. Range-reads the archive off disk instead
  of loading it: the central directory is parsed from the tail, and each member
  is fetched by absolute offset through `Blob.slice()`. Replaced JSZip, which
  had no random-access path. Supports stored/deflated members and Zip64.
- `workers/worldScan.worker.ts` — coordinator. Lists the save through
  `source.ts`, enumerates one dimension's `.mca` entries, reads them with
  **bounded read-ahead**, and feeds a pool of scan workers the bytes *as
  stored*. The scheduler itself is `workers/pool.ts` (`runPool`, written
  against a `PoolWorker` interface so tests can drive it), and
  `parseRegionPath()` is `workers/regionPath.ts` — both split out of the
  worker because importing a worker entry registers its `self` listener.
- `workers/regionScan.worker.ts` — pool member. One wasm instance per worker,
  inflates its region (`DecompressionStream('deflate-raw')`) and scans it.
  Deliberately independent instances: no `SharedArrayBuffer` and no
  `wasm-bindgen-rayon`, because GitHub Pages cannot set the COOP/COEP headers
  cross-origin isolation requires.
- `components/worldmap/` — the single-canvas map (X/Z plane), split so the
  canvas maths stands apart from the React wiring:
  - `WorldMap.tsx` — the component. Refs, hover/zoom state, the pointer and
    wheel handlers, and the `requestAnimationFrame` scheduling. Clicking a pin
    (a press that travelled < `CLICK_SLOP` px) copies its `x y z`.
  - `view.ts` — `View`, the `projection()` world↔screen pair that every hit
    test and every draw goes through, `fitView()`, `niceStep()`, the zoom clamp.
  - `render.ts` — `drawMap()`, the only code that touches the canvas. It reads
    its whole world from the `Scene` argument and never touches React state.
  - `columns.ts` — `columnAt()`, the hit test that resolves a screen point to
    the column of matches sharing one X/Z, plus `sameColumn()`/`columnCoords()`.
  - `useInertia.ts` (release glide), `useCopyToast.ts` (click-to-copy and its
    confirmation), `clipboard.ts` (async clipboard, textarea fallback).
  - `MapTooltip.tsx`, `MapHud.tsx` — the HTML chrome floating over the canvas.
- `pages/docs/Docs.tsx` + `docs-main.tsx` — the `/docs` page: logo, wordmark,
  and the prose from `content/docs.md`, imported `?raw` and rendered by
  `react-markdown` through an explicit element map (no typography plugin). It is
  a **second static entry point**, not a route: `frontend/docs/index.html` is
  listed in `build.rollupOptions.input`, so it builds to `dist/docs/index.html`
  and Pages serves it on a cold load.
  Note `Docs.tsx` and `docs-main.tsx` must not collide case-insensitively on
  Windows — that is why the entry isn't `docs.tsx`.
- `pages/legal/LegalPage.tsx` — `/privacy/` and `/terms/` (`frontend/privacy/`,
  `frontend/terms/`, in `build.rollupOptions.input`), rendering
  `content/privacy.md` / `content/terms.md` through the shared
  `components/layout/Prose.tsx` (also used by docs). Google's OAuth consent
  screen links both, so their URLs must not move, and **the privacy policy
  must be updated whenever what the API stores changes.**
- `pages/notfound/NotFound.tsx` + `not-found-main.tsx` — the third static entry
  point, mounted from `frontend/404.html`. It builds to `dist/404.html` at the
  site root, which is where Pages looks for the page to serve on an unknown
  path. Static like the other two: there is no client-side router to catch the
  miss. Vite's dev and preview servers would fall back to `index.html` for a
  miss, so `notFoundFallback()` in `vite.config.ts` intercepts any path no file
  backs and serves this page with a 404 status — local behaviour matches Pages.
- **UI vocabulary:** a stored scan result is a **reading**, and the verb is
  **keep** ("Keep this reading", "Your readings"). User-facing copy never says
  "save" for this, because a *save* is the Minecraft world being scanned. Code
  identifiers (`SavedScan`, `saveScan`) and the `/scans/` URL keep their names.
- `pages/scans/SavedScans.tsx` — the `/scans/` page (`frontend/scans/index.html`,
  in `build.rollupOptions.input` like docs): the account's saved scans, newest
  *scan* first, grouped by day. Cards are `components/scans/`: pressing one
  expands it in place into the same `WorldMap` the index page draws (one open
  at a time — the page owns `openId`; Escape or × closes). The card fetches the
  coordinates on open and drops them once the close animation ends, so only one
  scan's matches are ever resident. Cards also rename (inline) and delete.
  `lib/savedScans.ts` is the API client; `lib/coordsCodec.ts` packs the
  coordinates (zigzag deltas → byte planes → gzip, ~0.1–1 byte per match) in
  the browser, and the API stores that blob opaquely.
- `lib/api.ts` (fetch wrapper, token storage + `subscribeToken`, `accountsEnabled`), `lib/auth.ts`
  (sign-in/out, `/me`, delete, `pingApi()` wake-up for the cold-starting free
  host), `lib/googleIdentity.ts` (loads Google Identity Services on demand and
  renders its button), `lib/useSignedIn.ts` (token presence, reactive).
  `components/auth/GoogleSignInButton.tsx` is the one sign-in button: a styled
  pill with GIS's real button laid over it at zero opacity, because GIS only
  issues a token from a click inside its own iframe. `AccountMenu.tsx` (mounted
  top-right on the index and scans pages) and `SignInDialog.tsx` (opened by a
  signed-out Save) both use it, and follow the token via `subscribeToken` so
  either can start the session.
- **Content-Security-Policy.** `contentSecurityPolicy()` in `vite.config.ts`
  stamps a CSP `<meta>` into every built page (Pages cannot send headers; the
  session token in `localStorage` is what it protects). Build only — the dev
  server needs inline HMR scripts. A new external origin (script, API, image,
  iframe) must be added there, or it is blocked. e2e specs import `test` from
  `e2e/test.ts`, which fails any test that logs a CSP violation.
- `assets/PortalLoader.tsx`, `index.css` (Tailwind v4 + ambient background
  animation).
- `assets/icons/*.svg` — icons live here as standalone files, imported as
  components via `vite-plugin-svgr` (`import Icon from './assets/icons/x.svg?react'`).
  They keep `currentColor`/`stroke="currentColor"` so colour and sizing stay with
  the Tailwind classes at the call site. Don't paste icon markup back inline.

## Cross-cutting invariants (don't break these)

1. **Bounded read-ahead is mandatory.** One dimension of a large save is ~1.2 GB
   across a few hundred region files. `runPool` (`workers/pool.ts`) keeps at
   most `workers + 2` region buffers resident — counting every buffer alive
   anywhere: being read, queued, inside a worker, or awaiting its turn to be
   aggregated — and the reader parks when it hits that bound. Those are the
   members *as stored*: out of a zip that is the compressed form and each worker
   inflates its own, so the true peak is that bound plus one inflated region per
   worker; out of a folder the stored form is already inflated and nothing is
   duplicated, which makes the folder case the cheaper of the two despite the
   bigger buffers. Blowing this bound is the one change that turns the design
   into a tab crash. Treat it as load-bearing.
2. **`parseRegionPath()` is the source of truth for dimension-from-path.** A
   member is a region file only if its path is `…/region/<name>.mca|.mcc`, and
   the dimension comes from the parent dir (`DIM-1`→nether, `DIM1`→end, else
   overworld). It also returns the `world` root above that, which is how a
   selection holding two worlds is rejected instead of silently plotting both on
   one map — easy to hit with a folder, since `saves/` is one level up.
3. **Coordinates cross the wasm boundary as a flat `Int32Array`** of `x, y, z`
   triples, never as objects. A dense block yields hundreds of millions of
   matches; per-match object marshalling costs more than the scan itself. They
   become `[{x,y,z}]` exactly once, in `lib/scanWorld.ts` (a saved scan's do
   so in `lib/coordsCodec.ts`, its own boundary).
4. **React Compiler is on.** `babel-plugin-react-compiler` + strict
   `eslint-plugin-react-hooks` v7. Practical rules, mainly in
   `components/worldmap/`:
   - **No `setState` in an effect body.** Put state updates in event /
     `requestAnimationFrame` / `ResizeObserver` callbacks instead.
   - Read live view/hover state from refs inside the canvas `draw`.
   - Lazy ref init via `if (ref.current == null)`.
   - When cancelling an animation frame on cleanup, **null the ref afterwards** —
     a stale non-null `rafRef` wedges `scheduleDraw` across a StrictMode remount.
5. **`WorldMap` consumes `matches: [{ x, y, z }]`** in absolute world
   coordinates. That shape is the contract; the scan result around it
   (`{ blockType, dimension, count, truncated, matches }`) is just local state.
6. **The Rust scanner was verified byte-identical to the Python oracle**, which
   has since been removed from the tree (`25a0c22`; `scanner/README.md` still
   describes the cross-check). A change to `scanner/src/nbt.rs` or
   `src/region.rs` should be re-checked against it from git history — same
   count, same match list, same order. Today's `backend/` is unrelated.
7. **A folder's paths are captured on the main thread.**
   `File.webkitRelativePath` is the only record of where in a save a file sits,
   and it does **not** survive the structured clone into a worker — read it
   there and every file reports `''`, so no region file is ever found.
   `SavePicker` pairs each `File` with its path into a `FolderFile` before
   posting.
8. **Accounts are optional and never touch a scan.** With `VITE_API_URL` or
   `VITE_GOOGLE_CLIENT_ID` unset, `accountsEnabled` is false and `AccountMenu`
   renders nothing; the app must stay fully usable signed out and with the API
   down. No save bytes or paths ever go to the API. The one exception is
   opt-in: pressing Save sends that *result* — block, dimension, the save's
   name, counts and the packed coordinates — and nothing else. Sessions are
   opaque bearer tokens in `localStorage` (hash stored server-side), not
   cookies: Pages and Cloud Run are different sites, so a cookie would be
   third-party and blocked. Hence CORS has `allow_credentials=False`.

## Known risks / TODO

- **The accounts API cold-starts.** Cloud Run scales to zero (`--min-instances 0`,
  `--max-instances 1` to stay free and match the tiny DB pool) and
  Neon suspends an idle database, so the first request after idle is slow.
  `AccountMenu` pings `/health` (no DB call) on load to hide it, and the
  engine uses `pool_pre_ping` because Neon drops idle connections. Use Neon's
  *direct* connection string, not the `-pooler` host.
- **The API must stay free.** Keep `--max-instances 1` and the small instance
  in `deploy.sh`, the per-user session cap, and the in-memory abuse limits in
  `backend/app/limits.py` (body size, per-user and sign-in rates, daily
  egress budget — sound only *because* there is one instance; never key them
  on client IP, which Cloud Run lets the client spoof); a $1 budget unlinks billing
  (`infra/billing-killswitch/`), which takes the API down but never the site.
- **Schema changes go through Alembic** (`backend/migrations/`); the container
  runs `alembic upgrade head` on boot. Keep models portable (no PG-only types)
  — the tests run on SQLite.

- **`DecompressionStream('deflate-raw')` is a hard requirement *for zips*.** It
  is what inflates zip members, and it rules out Chrome < 103, Safari < 16.4 and
  Firefox < 113. `assertDecompressionSupported()` runs inside `openZip()` and
  fails the scan up front with an explanation rather than letting the
  constructor throw mid-run. A folder scan never inflates anything at this
  layer, so it works on older browsers — don't hoist that assert back out.
- **Directory input is `webkitdirectory`, not the File System Access API.**
  `showDirectoryPicker()` is Chromium-only and absent from `lib.dom.d.ts`;
  `webkitdirectory` covers Chrome, Edge, Firefox 50+ and Safari 11.1+. It is
  declared as a JSX attribute by a module augmentation in `vite-env.d.ts` —
  which needs that file's `export {}` to stay put, or the block stops being an
  augmentation and shadows React's types wholesale.
- **Chrome's directory picker says "upload N files".** Nothing is uploaded and
  nothing is even read — the hint text under the input pre-empts the wording.
  Drag-and-drop via `webkitGetAsEntry()` would avoid the prompt entirely; note
  that dropped files have an empty `webkitRelativePath` and the path must be
  rebuilt from the entry's `fullPath`.
- **A folder can change under the scan.** A `File` is a snapshot of a path, size
  and mtime; if Minecraft rewrites a region mid-scan the read fails, and
  `openFolder` turns that into "close the world in Minecraft". A zip cannot do
  this. Telling people to close the world first is the only real fix.
- **The reader trusts the central directory, never the local headers.** Local
  headers give the data offset and nothing else — a zipper that streamed its
  output leaves the sizes there zero and writes them after the payload.
- **Zip64 is exercised only by archives over 4 GB**, which neither `testing/`
  zip is. That path is the least-tested part of `workers/zip.ts`.
- **Low-RAM and mobile clients** do work a server used to do, so they get
  slower, not faster. Accepted. If it ever matters, the Python service could
  come back as an opt-in fallback — never the default.
- Optional: have `WorldMap` read the coordinate triples directly instead of
  `[{x,y,z}]`, which would also speed up the canvas draw.
